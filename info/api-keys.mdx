An API key is the credential your server, script, or CI job uses to call Kernel without an interactive login. Treat it like a password: keep it out of client-side code, store it in a secret manager, and rotate it when access changes.

Kernel only returns the plaintext key once, when you create it. Save the `key` value immediately. After that, Kernel only shows the masked value.

## Before you start

You need one existing Kernel credential to create another API key:

- Set `KERNEL_API_KEY` before running the SDK examples.

API keys can be **org** or **project** scoped:

- Omit `project_id` to create an org-scoped key that can access resources across your organization.
- Set `project_id` to create a project-scoped key that can only access resources in that project.
- When you authenticate with a project-scoped key, you can only create another project-scoped key for the same project.

Organization/project scope sets the key's boundary. A `policy` separately limits which actions and resources it can access inside that boundary. Both organization- and project-scoped keys can have policies.

## Create an API key

Use the SDKs when your backend needs to provision keys for environments, customers, or automation jobs.

### SDKs

<CodeGroup>
```typescript TypeScript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel({
  apiKey: process.env.KERNEL_API_KEY,
});

const apiKey = await kernel.apiKeys.create({
  name: 'staging-ci',
  days_to_expire: 30,
  project_id: 'proj_staging_9f3k',
});

console.log(apiKey.key); // Save this value now. Kernel won't show it again.
console.log(apiKey.id, apiKey.masked_key);
```

```python Python
import os
from kernel import Kernel

client = Kernel(api_key=os.environ["KERNEL_API_KEY"])

api_key = client.api_keys.create(
    name="staging-ci",
    days_to_expire=30,
    project_id="proj_staging_9f3k",
)

print(api_key.key)  # Save this value now. Kernel won't show it again.
print(api_key.id, api_key.masked_key)
```

```go Go
package main

import (
	"context"
	"fmt"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	apiKey, err := client.APIKeys.New(ctx, kernel.APIKeyNewParams{
		Name:         "staging-ci",
		DaysToExpire: kernel.Int(30),
		ProjectID:    kernel.String("proj_staging_9f3k"),
	})
	if err != nil {
		panic(err)
	}

	fmt.Println(apiKey.Key) // Save this value now. Kernel won't show it again.
	fmt.Println(apiKey.ID, apiKey.MaskedKey)
}
```
</CodeGroup>

## Scope a key to specific resources

By default, an API key can do anything in its organization or project. Add a `policy` when you create a key to limit what it can do. Keys created without `policy` work exactly as before.

Use scoped keys when you hand a credential to code you trust less than your backend, such as an AI agent or a short-lived job.

### How policies work

A policy is a list of **statements**. Each statement allows one **action** on one **resource**, and the key is denied everything no statement allows.

- A **resource** selects one project-owned object, such as `projects/{project_id}/extensions/{extension_id}`, an organization-owned object, such as `credential_providers/{provider_id}`, or a container such as `projects/{project_id}/*` or `organizations/{org_id}/*`.
- An **action** is an exact name such as `browsers:use`, `extensions:read`, or `api_keys:create`. A container wildcard grants that action throughout the container, not every action.

Some operations need more than one action. For example, creating a browser with a profile needs `browsers:create` and `browsers:use` on the project, plus `profiles:use` on that profile. See [API key permissions](/info/api-key-permissions) for every action and what each operation requires.

Policies cover browsers, profiles, vaults, proxies, extensions, telemetry destinations, browser pools, apps, managed auth, credentials, organization/project administration, API keys, audit logs, search, and the configuration registry. Start with a [policy example](/info/api-key-policy-examples) for your workload.

### Create a scoped key

This key can create and control browsers in one project, only with profile `prof_7h2kq9x4m1` or no profile, and expires in one hour:

<CodeGroup>
```typescript TypeScript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel({
  apiKey: process.env.KERNEL_API_KEY,
});

const apiKey = await kernel.apiKeys.create({
  name: 'checkout-agent-run-4812',
  project_id: 'proj_staging_9f3k',
  expires_at: new Date(Date.now() + 60 * 60 * 1000).toISOString(),
  policy: {
    statements: [
      { action: 'browsers:create', resource: 'projects/proj_staging_9f3k/*' },
      { action: 'browsers:use', resource: 'projects/proj_staging_9f3k/*' },
      { action: 'profiles:use', resource: 'projects/proj_staging_9f3k/profiles/prof_7h2kq9x4m1' },
    ],
  },
});

console.log(apiKey.key); // Save this value now. Kernel won't show it again.
```

```python Python
import os
from datetime import datetime, timedelta, timezone

from kernel import Kernel

client = Kernel(api_key=os.environ["KERNEL_API_KEY"])

api_key = client.api_keys.create(
    name="checkout-agent-run-4812",
    project_id="proj_staging_9f3k",
    expires_at=datetime.now(timezone.utc) + timedelta(hours=1),
    policy={
        "statements": [
            {"action": "browsers:create", "resource": "projects/proj_staging_9f3k/*"},
            {"action": "browsers:use", "resource": "projects/proj_staging_9f3k/*"},
            {"action": "profiles:use", "resource": "projects/proj_staging_9f3k/profiles/prof_7h2kq9x4m1"},
        ],
    },
)

print(api_key.key)  # Save this value now. Kernel won't show it again.
```
</CodeGroup>

### Expiry and revocation

- Use `expires_at` for an exact expiry, such as minutes from now, instead of `days_to_expire`. When you create a key with a policy, it can't outlive the issuing credential unless that credential holds `api_keys:issue_beyond_expiry` on the target. Kernel returns `400` for an expiry it can't honor; it never silently shortens the requested lifetime.
- Expired and deleted keys can't authenticate new API requests.
- Deleting a key through the API or dashboard, or rotating it with `expire_in_days: 0`, also ends browser sessions associated with that key, including pool browsers it acquired and hasn't released. Cleanup runs asynchronously and discards unsaved profile changes.
- Grace-period expiry and natural expiry do **not** end existing browsers. Delete those browsers explicitly if you need to stop them.
- Connection URLs (CDP, WebDriver, live view) stop working when their browser ends, not when the key stops authenticating.
- If browser cleanup can't be scheduled, deletion or immediate rotation fails without committing the key change.
- Rotating a scoped key keeps its policy.

<Note>
Automatic cleanup only covers browsers associated with the key. Some browsers created before this behavior was introduced may not have that association. Delete those browsers directly. Cleanup doesn't undo profile changes you've already saved, delete browser pools, or stop app invocations or deployments.
</Note>

### Delegate a narrower key

You can use a scoped key to create another scoped key:

1. Grant the issuer `api_keys:create` on the new key's project or organization container.
2. Supply a `policy` whose statements are covered by the issuer's policy, and keep the new key inside the issuer's organization/project boundary.
3. Set the new key's expiry no later than the issuer's expiry, or grant the issuer `api_keys:issue_beyond_expiry` on that container and request a finite lifetime of at most 3650 days.

For example, an issuer with `api_keys:create` and `browsers:use` on a project can issue a key with only `browsers:use` on one browser in that project. Use the same SDK creation call shown above with the narrower policy.

Use `api_keys:read` to inspect keys, `api_keys:write` to rename them, `api_keys:delete` to revoke them, and `api_keys:rotate` to replace them. When a scoped key rotates another key, it must also cover the target key's policy, and the replacement's expiry follows the same rule as creation, with `api_keys:issue_beyond_expiry` checked on the existing key. These permissions are separate, so you can grant metadata access without granting key issuance or rotation.

### Allow longer-lived child keys

Use an unscoped credential to issue a trusted key with `api_keys:issue_beyond_expiry`. This permission doesn't grant creation, rotation, or resource access by itself.

<CodeGroup>
```typescript TypeScript
const issuer = await kernel.apiKeys.create({
  name: 'ci-key-issuer',
  project_id: 'proj_staging_9f3k',
  days_to_expire: 30,
  policy: {
    statements: [
      { action: 'api_keys:create', resource: 'projects/proj_staging_9f3k/*' },
      { action: 'api_keys:issue_beyond_expiry', resource: 'projects/proj_staging_9f3k/*' },
      { action: 'browsers:use', resource: 'projects/proj_staging_9f3k/*' },
    ],
  },
});
```

```python Python
issuer = client.api_keys.create(
    name="ci-key-issuer",
    project_id="proj_staging_9f3k",
    days_to_expire=30,
    policy={
        "statements": [
            {"action": "api_keys:create", "resource": "projects/proj_staging_9f3k/*"},
            {"action": "api_keys:issue_beyond_expiry", "resource": "projects/proj_staging_9f3k/*"},
            {"action": "browsers:use", "resource": "projects/proj_staging_9f3k/*"},
        ],
    },
)
```
</CodeGroup>

Authenticate with `issuer.key` to create a child with `days_to_expire: 365` and only `browsers:use` on this project. Its expiry is one year, not silently shortened to the issuer's 30 days. Without the special permission, that request returns `400`.

The child must have a finite expiry of at most 3650 days. Scoped callers cannot create or rotate keys whose policies contain `api_keys:issue_beyond_expiry`, so the child can't inherit this authority. Add `api_keys:rotate` separately to let the issuer rotate other keys.

<Warning>
Grant this permission only to trusted issuers. Their child keys can remain valid after the issuer expires or is revoked.
</Warning>

## Deployment API keys

When you deploy an app, Kernel mints a **deployment-scoped API key** for that deployment and injects it into the deployment (and every invocation it runs) as the `KERNEL_API_KEY` environment variable. Because the SDKs read `KERNEL_API_KEY` from the environment by default, your app can call the Kernel API as itself without you managing a key.

When you deploy with a scoped key, the deployment key inherits your policy narrowed to the deployment's project, plus your expiry. Deploying requires container-wide `deployments:create`, `deployments:delete`, and `invocations:write`. Add permissions for the operations your app performs, such as creating browsers or using profiles.

To invoke that deployment with a scoped key, grant `invocations:create` and every permission held by the deployment key. The invoking key must expire no earlier than the deployment key. Scoped callers run deployments with scoped runtime keys; deployments created with unrestricted keys require an unrestricted caller.

<Note>
Scoped deployment creation requires rollout enablement. If the API reports that scoped deployments aren't enabled, contact support. See the [app policy example](/info/api-key-policy-examples) for a deployment and invocation policy.
</Note>

Key points about deployment keys:

- **One key per deployment.** Each deploy (including a redeploy of the same app) mints a fresh deployment key. `KERNEL_API_KEY` is a [reserved environment variable](/apps/deploy#reserved-environment-variables) — a value you supply at deploy time is overridden by the injected key. To use your own long-lived key, pass it under a non-reserved name.
- **Lifecycle tied to the deployment.** A deployment key is released when it's no longer needed. For scoped deployments, it also expires at the deployer's expiry. When you redeploy, the new deployment supersedes the old one, and the old deployment's key is released once it is no longer needed — that is, once the superseded deployment is stopped **and** no invocation is still running on it.
- **Superseded deployments drain in-flight invocations.** If an invocation is still running on a deployment that gets superseded, its key is retained until that invocation completes; its expiry still applies, and the key is released afterward. An idle redeploy (nothing in flight) releases the old key immediately. In the rare case where an invocation's workflow terminates without releasing the key, a background sweep releases it after a grace period (~95 minutes). You do not need to manage any of this — it is automatic.

Revoking the deploying key doesn't revoke the deployment's key or stop its invocations. Stop the deployment and let in-flight invocations drain, or revoke the deployment key to stop further API requests.

If you need a credential whose lifetime you control (for CI, a persistent backend, or a resource that should outlive any single deployment), create an org- or project-scoped key as described above and pass it explicitly to the client. This only affects the calls your app makes — the platform still injects the deployment key and uses it to run the invocation and report its result, so you're choosing the credential for your own calls, not replacing the deployment key.

## List and inspect API keys

List keys to audit what exists. List and retrieve responses include `masked_key`, `project_id`, `project_name`, `created_by`, expiry metadata, and `policy` for scoped keys, but they don't include the plaintext key.

<CodeGroup>
```typescript TypeScript
for await (const apiKey of kernel.apiKeys.list({ limit: 20 })) {
  console.log(apiKey.id, apiKey.name, apiKey.masked_key);
}

const apiKey = await kernel.apiKeys.retrieve('key_01jwv4tn5m8k3q2v7x9p0a1bc2');
console.log(apiKey.project_id, apiKey.expires_at);
```

```python Python
import os
from kernel import Kernel

client = Kernel(api_key=os.environ["KERNEL_API_KEY"])

for api_key in client.api_keys.list(limit=20):
    print(api_key.id, api_key.name, api_key.masked_key)

api_key = client.api_keys.retrieve("key_01jwv4tn5m8k3q2v7x9p0a1bc2")
print(api_key.project_id, api_key.expires_at)
```

```go Go
package main

import (
	"context"
	"fmt"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	pager := client.APIKeys.ListAutoPaging(ctx, kernel.APIKeyListParams{
		Limit: kernel.Int(20),
	})
	for pager.Next() {
		apiKey := pager.Current()
		fmt.Println(apiKey.ID, apiKey.Name, apiKey.MaskedKey)
	}
	if err := pager.Err(); err != nil {
		panic(err)
	}

	apiKey, err := client.APIKeys.Get(ctx, "key_01jwv4tn5m8k3q2v7x9p0a1bc2")
	if err != nil {
		panic(err)
	}

	fmt.Println(apiKey.ProjectID, apiKey.ExpiresAt)
}
```
</CodeGroup>

## Rename or delete an API key

Rename a key when the owner or purpose changes. Delete a key when the workload no longer needs access.

<Warning>
An API key cannot delete itself. Authenticate with a different key when deleting a key, so the request cannot revoke the credential that is authorizing it. Deleting a key also ends its associated browsers asynchronously and discards their unsaved profile changes.
</Warning>

<CodeGroup>
```typescript TypeScript
await kernel.apiKeys.update('key_01jwv4tn5m8k3q2v7x9p0a1bc2', {
  name: 'staging-ci-rotated',
});

await kernel.apiKeys.delete('key_01jwv4tn5m8k3q2v7x9p0a1bc2');
```

```python Python
import os
from kernel import Kernel

client = Kernel(api_key=os.environ["KERNEL_API_KEY"])

client.api_keys.update(
    "key_01jwv4tn5m8k3q2v7x9p0a1bc2",
    name="staging-ci-rotated",
)

client.api_keys.delete("key_01jwv4tn5m8k3q2v7x9p0a1bc2")
```

```go Go
package main

import (
	"context"
	"fmt"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	apiKey, err := client.APIKeys.Update(
		ctx,
		"key_01jwv4tn5m8k3q2v7x9p0a1bc2",
		kernel.APIKeyUpdateParams{
			Name: "staging-ci-rotated",
		},
	)
	if err != nil {
		panic(err)
	}
	fmt.Println(apiKey.ID, apiKey.Name)

	if err := client.APIKeys.Delete(ctx, "key_01jwv4tn5m8k3q2v7x9p0a1bc2"); err != nil {
		panic(err)
	}
}
```
</CodeGroup>

## Rotate a key

`rotate` issues a replacement key in a single call and keeps the old key working for a short grace period, so your workload can switch over without downtime. The new key copies the rotated key's name, project scope, and policy, and—like create—Kernel returns the plaintext `key` only once.

Two optional parameters control the timing:

- `days_to_expire` sets the new key's lifetime in days (`1`-`3650`). Omit it to give the new key the same lifetime the rotated key originally had, or to never expire if the old key never did.
- `expire_in_days` sets how long the old key keeps working before it expires. Use `0` to revoke it immediately, or omit it for the default 7-day grace window. The old key stops authenticating automatically once the window passes—you don't need to delete it.

If the key you rotate with has no policy, these lifetime rules apply to every target, including keys with policies, and you don't need `api_keys:issue_beyond_expiry`.

If the key you rotate with has a policy, it needs `api_keys:rotate` on the target and must cover the target's policy. When the caller expires, the replacement must expire no later than the caller, or the caller must hold `api_keys:issue_beyond_expiry` on the target and request a finite lifetime of up to 3650 days. The same check applies when you omit `days_to_expire` and reuse the old lifetime. A disallowed expiry returns `400`, never a shortened replacement. A caller with a policy cannot rotate a key that itself carries `api_keys:issue_beyond_expiry`.

<CodeGroup>
```typescript TypeScript
const rotated = await kernel.apiKeys.rotate('key_01jwv4tn5m8k3q2v7x9p0a1bc2', {
  days_to_expire: 30,
  expire_in_days: 7,
});

console.log(rotated.key); // Save this value now. Kernel won't show it again.
console.log(rotated.id, rotated.masked_key);
```

```python Python
import os
from kernel import Kernel

client = Kernel(api_key=os.environ["KERNEL_API_KEY"])

rotated = client.api_keys.rotate(
    "key_01jwv4tn5m8k3q2v7x9p0a1bc2",
    days_to_expire=30,
    expire_in_days=7,
)

print(rotated.key)  # Save this value now. Kernel won't show it again.
print(rotated.id, rotated.masked_key)
```

```go Go
package main

import (
	"context"
	"fmt"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

		ctx,
		"key_01jwv4tn5m8k3q2v7x9p0a1bc2",
		kernel.APIKeyRotateParams{
			DaysToExpire: kernel.Int(30),
			ExpireInDays: kernel.Int(7),
		},
	)
	if err != nil {
		panic(err)
	}

	fmt.Println(rotated.Key) // Save this value now. Kernel won't show it again.
	fmt.Println(rotated.ID, rotated.MaskedKey)
}
```
</CodeGroup>

After you rotate a key:

1. Store the new plaintext key in your secret manager.
2. Deploy or restart the workload that uses `KERNEL_API_KEY`.
3. Verify the workload can call Kernel before the grace window ends.

To cut over immediately instead of using a grace window, pass `expire_in_days: 0`. The old key stops working, its associated browsers are ended asynchronously, and unsaved profile changes in those browsers are discarded. With a grace period, existing browsers keep running after the old key expires.

## Troubleshooting

| Error | What it means | What to do |
| --- | --- | --- |
| `400 Bad Request` | The name is missing, `days_to_expire` is outside `1`-`3650`, `expire_in_days` is outside `0`-`3650`, or `project_id` is empty. | Send a name, choose a valid expiry, or omit `project_id` for an org-scoped key. |
| `400 Bad Request` (rotate) | `days_to_expire` is shorter than `expire_in_days`, so the new key would expire before the old key's grace window ends. | Raise `days_to_expire` or lower `expire_in_days`. |
| `400 Bad Request` (scoped key) | The policy has an unknown action or a resource outside the key's organization or project, or the requested expiry exceeds the issuing or rotating credential's without the required permission. | Check [API key permissions](/info/api-key-permissions). Request an allowed expiry, or have an unscoped issuer grant `api_keys:issue_beyond_expiry`; its exception requires a finite expiry within 3650 days. |
| `401 Unauthorized` | Kernel couldn't authenticate the request. | Set a valid `KERNEL_API_KEY`. |
| `403 Forbidden` (`insufficient_scope`) | A scoped key is missing a permission. | The message names the missing action and resource. Add it to the policy. |
| `404 Not Found` | The project, API key, or a resource named in the policy doesn't exist, or the caller can't access it. | Check the ID. If you're using a project-scoped key, you can only rotate keys in that same project. |
