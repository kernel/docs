This guide walks the whole path end to end: install the SDK, create a cloud browser and drive it, watch what it's doing, and then serve a real workload from a [browser pool](/browsers/pools). Each step builds on the one before it, so work top to bottom the first time through.

## Install and authenticate

Install the CLI and log in:

```bash
# Using brew
brew install kernel/tap/kernel

# or using npm
npm install -g @onkernel/cli

kernel login
```

Create an API key for your code to use, and export it as `KERNEL_API_KEY` — the SDKs read it automatically:

```bash
kernel api-keys create --name quickstart
export KERNEL_API_KEY="<your-api-key>"
```

Then install the SDK for your language:

<CodeGroup>
```bash Typescript/Javascript
npm install @onkernel/sdk
```

```bash Python
pip install kernel
```

```bash Go
go get github.com/kernel/kernel-go-sdk
```
</CodeGroup>

## Create and drive a browser

`browsers.create()` boots a sandboxed Chromium instance in the cloud. The response carries everything you need to drive it — a CDP URL for Playwright or any CDP client, and a live view URL you can open in your own browser.

<CodeGroup>
```typescript Typescript/Javascript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel();

const kernelBrowser = await kernel.browsers.create();

const response = await kernel.browsers.playwright.execute(kernelBrowser.session_id, {
  code: `
    await page.goto('https://www.onkernel.com');
    return await page.title();
  `,
});

console.log(response.result);
console.log(kernelBrowser.browser_live_view_url);
```

```python Python
from kernel import Kernel

kernel = Kernel()

kernel_browser = kernel.browsers.create()

response = kernel.browsers.playwright.execute(
    id=kernel_browser.session_id,
    code="""
      await page.goto('https://www.onkernel.com')
      return await page.title()
    """,
)

print(response.result)
print(kernel_browser.browser_live_view_url)
```

```go Go
ctx := context.Background()
client := kernel.NewClient()

kernelBrowser, err := client.Browsers.New(ctx, kernel.BrowserNewParams{})
if err != nil {
	panic(err)
}

response, err := client.Browsers.Playwright.Execute(ctx, kernelBrowser.SessionID, kernel.BrowserPlaywrightExecuteParams{
	Code: `
		await page.goto('https://www.onkernel.com');
		return await page.title();
	`,
})
if err != nil {
	panic(err)
}

fmt.Println(response.Result)
fmt.Println(kernelBrowser.BrowserLiveViewURL)
```

```bash CLI
kernel browsers create --start-url https://www.onkernel.com
```
</CodeGroup>

You can also connect Playwright directly over CDP with `kernelBrowser.cdp_ws_url` instead of running code server-side — see [Control](/introduction/control) for every way to drive a browser.

<Info>
Browsers aren't free-running: after five seconds with nothing driving it, a browser enters [standby](/browsers/standby) and billing stops. Delete it explicitly with `browsers.delete_by_id()` when you're done — see [Termination & timeouts](/browsers/termination).
</Info>

## Watch what it's doing

Open the `browser_live_view_url` from the response in your own browser to watch the session in real time, and interact with it directly if you need to.

For sessions that already finished, [replays](/browsers/replays) record them as MP4s, and [browser telemetry](/browsers/telemetry/overview) streams network and console events. See [Observe](/introduction/observe) for the full picture.

## Serve a workload from a browser pool

`browsers.create()` is the right call while you're building. Once you're running the same task repeatedly — or need acquisition to be fast and predictable — switch to a [browser pool](/browsers/pools): a fixed set of identical browsers, already booted with your configuration, that you acquire from and release back.

The shape is **create the pool once, then acquire per task**:

<CodeGroup>
```typescript Typescript/Javascript
// Once, at deploy time or on startup — not in your request path
await kernel.browserPools.create({
  name: 'checkout-pool',
  size: 20,
  stealth: true,
});
```

```python Python
# Once, at deploy time or on startup — not in your request path
kernel.browser_pools.create(
    name="checkout-pool",
    size=20,
    stealth=True,
)
```

```go Go
// Once, at deploy time or on startup — not in your request path
if _, err := client.BrowserPools.New(ctx, kernel.BrowserPoolNewParams{
	Name:    kernel.String("checkout-pool"),
	Size:    20,
	Stealth: kernel.Bool(true),
}); err != nil {
	panic(err)
}
```

```bash CLI
kernel browser-pools create checkout-pool --size 20 --stealth
```
</CodeGroup>

Then, per task, acquire a browser, drive it, and release it in a `finally` block so it always goes back to the pool:

<CodeGroup>
```typescript Typescript/Javascript
import Kernel from '@onkernel/sdk';
import { chromium } from 'playwright';

const kernel = new Kernel();

const kernelBrowser = await kernel.browserPools.acquire('checkout-pool', {});

try {
  const browser = await chromium.connectOverCDP(kernelBrowser.cdp_ws_url);
  const context = browser.contexts()[0];
  const page = context.pages()[0];

  await page.goto('https://example.com');
  console.log(await page.title());
} finally {
  await kernel.browserPools.release('checkout-pool', {
    session_id: kernelBrowser.session_id,
  });
}
```

```python Python
import asyncio
from kernel import Kernel
from playwright.async_api import async_playwright

kernel = Kernel()

async def main():
    kernel_browser = kernel.browser_pools.acquire("checkout-pool")

    async with async_playwright() as playwright:
        try:
            browser = await playwright.chromium.connect_over_cdp(kernel_browser.cdp_ws_url)
            context = browser.contexts[0]
            page = context.pages[0]

            await page.goto('https://example.com')
            print(await page.title())
        finally:
            kernel.browser_pools.release(
                "checkout-pool",
                session_id=kernel_browser.session_id,
            )

asyncio.run(main())
```

```go Go
kernelBrowser, err := client.BrowserPools.Acquire(ctx, "checkout-pool", kernel.BrowserPoolAcquireParams{})
if err != nil {
	panic(err)
}

defer func() {
	if err := client.BrowserPools.Release(ctx, "checkout-pool", kernel.BrowserPoolReleaseParams{
		SessionID: kernelBrowser.SessionID,
	}); err != nil {
		panic(err)
	}
}()

response, err := client.Browsers.Playwright.Execute(ctx, kernelBrowser.SessionID, kernel.BrowserPlaywrightExecuteParams{
	Code: `
		await page.goto('https://example.com');
		return await page.title();
	`,
})
if err != nil {
	panic(err)
}

fmt.Println(response.Result)
```
</CodeGroup>

Three things to know before this goes to production:

- **Failing to release is the most common mistake.** An unreleased browser stays `acquired` until it times out, so the pool drains. Always release in a `finally` block.
- **`reuse: true` (the default) hands the *same* browser to the next caller**, cookies and logged-in sessions included. If you're acquiring on behalf of different end users, release with `reuse: false`.
- **Idle browsers in a pool aren't billed**, but the pool's capacity counts against your [concurrency limit](/info/pricing#concurrency-limits) whether or not its browsers are acquired.

Watch `available_count` to size the pool — see [Sizing a browser pool](/browsers/pools#sizing-a-browser-pool).

## Give each user their own login

If you're acting on behalf of many end users, each needs their own logged-in state — but a pool's profile is shared by every browser and loaded read-only, so it can't hold per-user logins. The pattern is to keep the base configuration on the pool and attach the user's profile after acquiring:

1. **Create the pool with no profile.** Stealth, proxies, extensions, and viewport still live on the pool; only the profile is left off, because a profile can only be loaded into a browser that was created without one.
2. **Acquire a browser** from the pool.
3. **Attach that user's profile** with `save_changes: true` using `kernel.browsers.update()`. Use [Managed Auth](/auth/overview) to keep those profiles logged in.
4. **Run your automation, then release with `reuse: false`.** Destroying the browser both persists the profile changes and stops that user's state from reaching the next acquirer.

<CodeGroup>
```typescript Typescript/Javascript
// Declare the pool once, separately from your workload runtime, with no profile attached
const pool = await kernel.browserPools.create({ name: "my-pool", size: 10 });

// Later, at runtime, acquire from the pool per user:
const browser = await kernel.browserPools.acquire("my-pool", {});

// Load this user's profile and persist any changes on destroy
await kernel.browsers.update(browser.session_id, {
  profile: { name: userId, save_changes: true },
});

// ... run your automation against browser.cdp_ws_url ...

// Destroy on release so the profile persists and no state leaks to the next user
await kernel.browserPools.release("my-pool", {
  session_id: browser.session_id,
  reuse: false,
});
```

```python Python
# Declare the pool once, separately from your workload runtime, with no profile attached
pool = kernel.browser_pools.create(name="my-pool", size=10)

# Later, at runtime, acquire from the pool per user:
browser = kernel.browser_pools.acquire("my-pool")

# Load this user's profile and persist any changes on destroy
kernel.browsers.update(
    browser.session_id,
    profile={"name": user_id, "save_changes": True},
)

# ... run your automation against browser.cdp_ws_url ...

# Destroy on release so the profile persists and no state leaks to the next user
kernel.browser_pools.release(
    "my-pool",
    session_id=browser.session_id,
    reuse=False,
)
```

```go Go
// Declare the pool once, separately from your workload runtime, with no profile attached.
// Later, at runtime, acquire from the pool per user:
browser, err := client.BrowserPools.Acquire(ctx, "my-pool", kernel.BrowserPoolAcquireParams{})
if err != nil {
	panic(err)
}

// Load this user's profile and persist any changes on destroy
if _, err := client.Browsers.Update(ctx, browser.SessionID, kernel.BrowserUpdateParams{
	Profile: shared.BrowserProfileParam{
		Name:        kernel.String(userID),
		SaveChanges: kernel.Bool(true),
	},
}); err != nil {
	panic(err)
}

// ... run your automation against browser.CdpWsURL ...

// Destroy on release so the profile persists and no state leaks to the next user
if err := client.BrowserPools.Release(ctx, "my-pool", kernel.BrowserPoolReleaseParams{
	SessionID: browser.SessionID,
	Reuse:     kernel.Bool(false),
}); err != nil {
	panic(err)
}
```
</CodeGroup>

<Info>
Releasing with `reuse: false` triggers a pool refill at the configured [fill rate](https://kernel.sh/docs/api-reference/browser-pools/create-a-browser-pool#body-fill-rate-per-minute), so the pool tops back up to `size` with fresh, profile-free browsers ready for the next user.
</Info>

See [Profiles with browser pools](/browsers/pools#profiles-with-browser-pools) for the underlying behavior.
