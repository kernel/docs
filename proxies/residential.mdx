title: "Residential Proxies"
---

Residential proxies route traffic through real residential IP addresses. They support advanced targeting options including city, state, and operating system.

## Routing and IP behavior

KERNEL routes residential proxy traffic across multiple providers. This expands destination coverage and allows connections to fall back when a provider rejects a destination. You use the same residential proxy configuration without managing separate provider integrations.

### Provider selection

Each browser session gets a preferred provider through a deterministic, weighted allocation. This isn't per-request random provider rotation. With the same session, proxy, and routing configuration, the preferred provider stays the same.

For each new connection, we consider the preferred provider, destination restrictions, and compatible alternatives. Compatibility depends on your proxy's targeting options and the destination port; an alternate provider isn't always available. Different destinations within a browser session may use different providers.

### Automatic failover

We route around known provider restrictions. When a provider returns a recognized destination-policy rejection during connection setup, we can retry through another compatible provider **before sending your browser's request to the destination**. We don't replay an origin request that has already been sent.

We temporarily cache provider-specific restrictions so subsequent connections can skip that provider for the affected destination. Attempts are bounded and share a connection-setup deadline. If no compatible route succeeds, the connection fails.

Website responses, including origin errors, rate limits, and bot challenges, don't trigger this failover. Switching providers doesn't guarantee access to a website.

### IP consistency

A consistent provider selection doesn't guarantee a consistent exit IP. Some provider routes use sticky sessions to request the same exit IP across connections, while others rotate IPs. Even connections to the same destination can get different IPs.

- **Open connections** stay on their current provider and exit IP. Routing updates affect new connections rather than interrupting open ones.
- **New connections** may use a different exit IP because of failover, routing updates, sticky-session expiry, or residential device availability.
- **Different destinations** may use different providers and exit IPs within the same browser session.

If you need a consistent exit IP across connections and browser sessions, use an [ISP proxy](/proxies/isp) instead.

## Configuration

Create a residential proxy with a target country:

<CodeGroup>
```typescript Typescript/Javascript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel();

const proxy = await kernel.proxies.create({
  type: 'residential',
  name: 'my-us-residential',
  config: {
    country: 'US'
  }
});

const browser = await kernel.browsers.create({
  proxy_id: proxy.id,
});
```

```python Python
from kernel import Kernel

kernel = Kernel()

proxy = kernel.proxies.create(
    type='residential',
    name='my-us-residential',
    config={
        'country': 'US'
    }
)

browser = kernel.browsers.create(proxy_id=proxy.id)
```

```go Go
package main

import (
	"context"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	proxy, err := client.Proxies.New(ctx, kernel.ProxyNewParams{
		Type: kernel.ProxyNewParamsTypeResidential,
		Name: kernel.String("my-us-residential"),
		Config: kernel.ProxyNewParamsConfigUnion{
			OfProxyNewsConfigResidentialProxyConfig: &kernel.ProxyNewParamsConfigResidentialProxyConfig{
				Country: kernel.String("US"),
			},
		},
	})
	if err != nil {
		panic(err)
	}

	browser, err := client.Browsers.New(ctx, kernel.BrowserNewParams{
		ProxyID: kernel.String(proxy.ID),
	})
	if err != nil {
		panic(err)
	}
	_ = browser
}
```
</CodeGroup>

## Configuration Parameters

- **`country`** - ISO 3166 country code. Must be provided when providing other targeting options.
- **`state`** - Two-letter state code. Only supported for US.
- **`city`** - City name (lowercase, no spaces, e.g., `sanfrancisco`, `newyork`).
- **`zip`** - US ZIP code (5 digits). Can only be used with `country` set to `US`. Cannot be combined with `city` or `state`.
- **`asn`** - Autonomous System Number. Conflicts with city and state.
- **`bypass_hosts`** (optional) - Array of hostnames that bypass the proxy and connect directly (max 100 entries)

## Advanced Targeting Examples

Kernel recommends using the least-specific targeting configuration that works for your use case. The more specific a configuration, the less available IPs there are, increasing the chance of a slow connection or no available connection (`no_peer` connection error).

### Target by City

Route traffic through a specific city:

<CodeGroup>

```typescript Typescript/Javascript
const proxy = await kernel.proxies.create({
  type: 'residential',
  name: 'la-residential',
  config: {
    country: 'US',
    state: 'CA',
    city: 'los_angeles'
  }
});
```

```Python Python
proxy = kernel.proxies.create(
    type='residential',
    name='la-residential',
    config={
        'country': 'US',
        'state': 'CA',
        'city': 'los_angeles'
    }
)
```

```go Go
proxy, err := client.Proxies.New(ctx, kernel.ProxyNewParams{
	Type: kernel.ProxyNewParamsTypeResidential,
	Name: kernel.String("la-residential"),
	Config: kernel.ProxyNewParamsConfigUnion{
		OfProxyNewsConfigResidentialProxyConfig: &kernel.ProxyNewParamsConfigResidentialProxyConfig{
			Country: kernel.String("US"),
			State:   kernel.String("CA"),
			City:    kernel.String("los_angeles"),
		},
	},
})
if err != nil {
	panic(err)
}
_ = proxy
```

</CodeGroup>

<Note>
If the city name is not matched, the API will return the best 10 city names from the state to help you find the correct city identifier.
</Note>

</CodeGroup>

<Note>
ZIP code targeting is US-only and cannot be combined with `state` or `city`. The exit IP will be in the geographic area of the requested ZIP code, but the IP's exact ZIP may differ slightly (e.g., requesting `90210` may route through `90401` in the same metro area).
</Note>

<Warning>
Not all ZIP codes have available residential IPs. If a ZIP code is unavailable, proxy creation will fail with a message suggesting alternatives: a nearby ZIP, city/state targeting, or country-only targeting.
</Warning>

## .gov support

Residential proxies with no targeting, country-only targeting, or US state targeting automatically route `.gov` requests through a compatible upstream provider. ZIP, ASN, and non-US state targeting may return `restricted_route_unavailable`.

You may [check proxy health](/proxies/overview#check-proxy-health) against a `.gov` URL before starting a browser.

## Bypass hosts

Configure specific hostnames to bypass the proxy and connect directly:

<CodeGroup>
```typescript Typescript/Javascript
const proxy = await kernel.proxies.create({
  type: 'residential',
  name: 'residential-with-bypass',
  config: {
    country: 'US',
  },
  bypass_hosts: [
    'localhost',
    'metadata.google.internal',
    '*.internal.company.com',
  ],
});
```

```python Python
proxy = kernel.proxies.create(
    type='residential',
    name='residential-with-bypass',
    config={
        'country': 'US',
    },
    bypass_hosts=[
        'localhost',
        'metadata.google.internal',
        '*.internal.company.com',
    ]
)
```

```go Go
proxy, err := client.Proxies.New(ctx, kernel.ProxyNewParams{
	Type: kernel.ProxyNewParamsTypeResidential,
	Name: kernel.String("residential-with-bypass"),
	Config: kernel.ProxyNewParamsConfigUnion{
		OfProxyNewsConfigResidentialProxyConfig: &kernel.ProxyNewParamsConfigResidentialProxyConfig{
			Country: kernel.String("US"),
		},
	},
	BypassHosts: []string{
		"localhost",
		"metadata.google.internal",
		"*.internal.company.com",
	},
})
if err != nil {
	panic(err)
}
_ = proxy
```
</CodeGroup>
