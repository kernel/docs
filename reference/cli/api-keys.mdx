---
title: "API Keys"
---

Manage [API keys](/info/api-keys) from the CLI. Native OAuth sessions can’t manage keys. Set `KERNEL_API_KEY` to a personal API key with the permissions you need, or use the dashboard.

<Tip>
For CI jobs, cloud services, and Kubernetes pods, use [workload identity federation](/info/workload-identity/overview) instead of an API key. There's no secret to store, and the credential expires in minutes. Service accounts, issuers, and federation rules are managed from the dashboard.
</Tip>

## `kernel api-keys create`

Create an API key. By default, the new key is org-wide. Pass `--project-id` to create a key whose own access is scoped to that project.

```bash
kernel api-keys create \
  --name staging-ci \
  --days-to-expire 30 \
  --project-id proj_staging_9f3k \
  --output json
```

| Flag | Description |
|------|-------------|
| `--name <name>` | API key name. Required. |
| `--days-to-expire <days>` | Number of days until expiry, from `1` to `3650`. Use this or `--expires-at`, not both. |
| `--expires-at <timestamp>` | Exact future expiry in RFC 3339 format. See [issuer expiry limits](/info/api-keys#delegate-a-narrower-key). |
| `--policy <json>` | Grant only the actions and resources in this [policy](/info/api-key-policy-examples). Without a policy, the key is unrestricted within its project or organization. |
| `--service-account-id <id>` | Issue a key for this service account instead of yourself. Requires organization administrator access, `--project-id`, and a non-empty `--policy`. |
| `--project-id <project_id>` | Create a project-scoped API key for this project. Omit for org-wide. |
| `--output json`, `-o json` | Output the raw JSON object, including the plaintext `key` on create. |

<Info>
  `--project-id` controls the access scope of the new API key. The global `--project` flag only scopes the CLI request you're making.
</Info>

## `kernel api-keys list`

List API keys in the authenticated organization. API keys are masked. By default, the list shows active keys: keys that are neither deleted nor expired.

```bash
kernel api-keys list --limit 20
```

| Flag | Description |
|------|-------------|
| `--limit <n>` | Maximum number of results to return. |
| `--offset <n>` | Number of results to skip. |
| `--status <status>` | `active`, `expired`, `deleted`, or `all`. Use `--status all` instead of the deprecated list flag `--include-deleted`. |
| `--name <name>`, `--query <text>` | `--name` matches an exact name. `--query` searches names, creators, and projects; IDs and masked keys must match exactly. |
| `--project-id <id>`, `--created-by <id>` | Filter by project (or `org` for organization-wide keys) or creator. |
| `--principal-type <type>`, `--service-account-id <id>` | Filter by principal type (`user` or `service_account`) or service account. |
| `--sort-by <field>`, `--sort-direction <direction>` | Sort by `created_at`, `name`, `expires_at`, or `last_used_at`, in `asc` or `desc` order. |
| `--output json`, `-o json` | Output the raw JSON array. |

## `kernel api-keys get <id>`

Show one API key by ID. The response includes the masked key and metadata, not the plaintext key.

```bash
kernel api-keys get key_01jwv4tn5m8k3q2v7x9p0a1bc2
```

| Flag | Description |
|------|-------------|
| `--include-deleted` | Include soft-deleted API keys in the lookup. |
| `--output json`, `-o json` | Output the raw JSON object. |

## `kernel api-keys update <id>`

Rename an API key, replace its policy, or both. Supply at least one of `--name` and `--policy`.

```bash
kernel api-keys update key_01jwv4tn5m8k3q2v7x9p0a1bc2 --name staging-ci-rotated
```

| Flag | Description |
|------|-------------|
| `--name <name>` | New API key name. |
| `--policy <json>` | Complete replacement policy. Omitted statements are not retained. |
| `--output json`, `-o json` | Output the raw JSON object. |

## `kernel api-keys rotate <id>`

Issue a replacement API key. The rotated key keeps working for a grace period so you can migrate callers without downtime.

```bash
kernel api-keys rotate key_01jwv4tn5m8k3q2v7x9p0a1bc2 \
  --days-to-expire 90 \
  --expire-in-days 7 \
  --yes \
  --output json
```

| Flag | Description |
|------|-------------|
| `--days-to-expire <days>` | Lifetime of the new key, from `1` to `3650` days. Omit to reuse the rotated key's lifetime. |
| `--expire-in-days <days>` | Grace period before the rotated key expires. Pass `0` to expire it immediately; omit for the default of 7 days. |
| `--yes`, `-y` | Skip the confirmation prompt. |
| `--output json`, `-o json` | Output the raw JSON object, including the new one-time plaintext key. |

<Warning>
  Save the new plaintext key when you rotate it. Kernel won't return it again.
  With `--expire-in-days 0`, the old key's associated browsers are ended asynchronously
  and their unsaved profile changes are discarded. A grace-period expiry doesn't end
  existing browsers.
</Warning>

## `kernel api-keys delete <id>`

Delete an API key. Its associated browsers are ended asynchronously, and unsaved profile changes in those browsers are discarded.

<Note>
  Automatic cleanup only covers browsers associated with the key. Some older browsers
  may be unaffected; delete those browsers directly. See [API key expiry and revocation](/info/api-keys#expiry-and-revocation).
</Note>

```bash
kernel api-keys delete key_01jwv4tn5m8k3q2v7x9p0a1bc2 --yes
```

| Flag | Description |
|------|-------------|
| `--yes`, `-y` | Skip the confirmation prompt. |

## Aliases

You can also use `kernel api-key`, `kernel apikeys`, or `kernel apikey`.
