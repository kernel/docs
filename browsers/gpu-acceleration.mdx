---
title: GPU Acceleration
---

GPU acceleration enables GPU-accelerated rendering in Kernel browsers, providing enhanced performance for graphics-intensive workloads.

<Warning>
GPU acceleration is only available for headful browsers and does not support [standby mode](/browsers/standby). GPU browsers have [separate pricing](https://kernel.sh/pricing) from headless or headful browsers.
</Warning>

## Enable GPU acceleration

Set the `gpu` parameter to `true` when creating a browser:

<CodeGroup>
```typescript Typescript/Javascript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel();

const kernelBrowser = await kernel.browsers.create({
  gpu: true
});
```

```python Python
from kernel import Kernel

kernel = Kernel()

kernel_browser = kernel.browsers.create(
    gpu=True
)
```

```go Go
package main

import (
	"context"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	kernelBrowser, err := client.Browsers.New(ctx, kernel.BrowserNewParams{
		GPU: kernel.Bool(true),
	})
	if err != nil {
		panic(err)
	}
	_ = kernelBrowser
}
```
</CodeGroup>

You can also enable GPU acceleration in the dashboard when deploying a browser under **Advanced Configuration**.

## Request more video memory

A GPU browser gets 3 GiB of video memory by default, with 4 vCPUs and 6 GiB of memory. For WebGL scenes, large canvases, or video that run out of video memory, set `video_memory` to `6GiB`. That browser gets 6 GiB of video memory, 8 vCPUs, and 12 GiB of memory.

<CodeGroup>
```typescript Typescript/Javascript
import Kernel from '@onkernel/sdk';

const kernel = new Kernel();

const kernelBrowser = await kernel.browsers.create({
  gpu: true,
  video_memory: '6GiB',
});
```

```python Python
from kernel import Kernel

kernel = Kernel()

kernel_browser = kernel.browsers.create(
    gpu=True,
    video_memory="6GiB",
)
```

```go Go
package main

import (
	"context"

	"github.com/kernel/kernel-go-sdk"
)

func main() {
	ctx := context.Background()
	client := kernel.NewClient()

	kernelBrowser, err := client.Browsers.New(ctx, kernel.BrowserNewParams{
		GPU:         kernel.Bool(true),
		VideoMemory: kernel.BrowserVideoMemory6GiB,
	})
	if err != nil {
		panic(err)
	}
	_ = kernelBrowser
}
```

```bash CLI
kernel browsers create --gpu --video-memory 6GiB
```
</CodeGroup>

`video_memory` accepts `3GiB` or `6GiB` and requires `gpu: true`. The `3GiB` and `6GiB` values need SDK version 0.141.0 or later. You can't set `memory` on a GPU browser, because `video_memory` determines its memory. The browser response includes `video_memory` and `memory`, so you can confirm the allocation you received.

<Note>
`2GiB` and `4GiB` are deprecated aliases for `3GiB` and `6GiB`. Requests that send them still work and get the new allocation, and responses report `3GiB` or `6GiB`. Switch to the new values when you upgrade your SDK.
</Note>

A browser with 6 GiB of video memory is billed for its 12 GiB of memory, so it costs twice the [standard GPU rate](/info/pricing#usage-rates).

These browsers come from separate capacity. If none is available, creation fails with HTTP 529 and the `no_gpu_browsers_available` code instead of falling back to 3 GiB of video memory. Retry later, or omit `video_memory` to get a standard GPU browser.

## Use cases

GPU acceleration is useful for:
- High performance live view streaming
- Rendering complex 3D graphics or WebGL content
- Video processing and playback
- Canvas-heavy applications

<Note>
GPU acceleration speeds up page rendering, not screenshot capture. CDP's `Page.captureScreenshot` latency is unaffected by GPU. [Computer controls screenshots](/browsers/computer-controls#take-screenshots) see a small speedup with GPU enabled.
</Note>

## Availability

GPU acceleration is available on [Start-Up and Enterprise plans](https://kernel.sh/pricing).
