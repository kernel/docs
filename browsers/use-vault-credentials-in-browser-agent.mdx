---
title: "Use Vault Credentials in a Browser Agent"
description: "Collect credentials outside your agent, then let it request a scoped browser fill"
---

you have a browser agent and want it to complete a login form without passing a password through its prompt or tool arguments. store the fields in a [credential item](/vaults/credentials), collect them through your trusted application, and expose a scoped [fill](/vaults/fill) tool to the agent.

this recipe leaves navigation and login handling with your agent. use [managed auth](/auth/overview) if you want KERNEL to run and maintain the login instead. use the [payments cookbook](/browsers/enable-payments-in-browser-agent) for payment-card data.

<Warning>
  fill doesn't isolate a password from an agent that can inspect the browser. it keeps the password out of the fill request and response, but writes it into the page. don't claim secret isolation if your agent has unrestricted browser access.
</Warning>

## Before you start

use a login page you control with inputs matching `#username` and `#password`. set `LOGIN_URL` to its exact https url and use a test account. set `KERNEL_API_KEY` and `KERNEL_PROJECT_ID` in your trusted backend. the examples require typescript or python sdk version `0.103.0` or later.

your application owns the vault, collection link, browser session, and destination policy. the end user provides credentials in the collection form. the agent receives the task and a scoped tool, not the collection link or a broad api key.

## 1. Prepare the item in your backend

<CodeGroup>

```typescript TypeScript
import Kernel from "@onkernel/sdk";

const projectID = process.env.KERNEL_PROJECT_ID;
const loginURL = process.env.LOGIN_URL;
if (!projectID || !loginURL || new URL(loginURL).protocol !== "https:") {
  throw new Error("set KERNEL_PROJECT_ID and an HTTPS LOGIN_URL");
}
const kernel = new Kernel({ projectID, maxRetries: 0 });
const vault = await kernel.vaults.upsert({ name: "account-portal-demo" });
const item = await kernel.vaults.items.upsert("portal-login", {
  id_or_name: vault.id,
  type: "credential",
  spec: {
    description: "Account Portal",
    fields: {
      username: { type: "email", sensitive: false, required: true },
      password: { type: "password", sensitive: true, required: true },
    },
  },
});
```

```python Python
import os
from urllib.parse import urlparse

from kernel import Kernel

login_url = os.environ["LOGIN_URL"]
if urlparse(login_url).scheme != "https":
    raise RuntimeError("LOGIN_URL must use HTTPS")
kernel = Kernel(project_id=os.environ["KERNEL_PROJECT_ID"], max_retries=0)
vault = kernel.vaults.upsert(name="account-portal-demo")
item = kernel.vaults.items.upsert(
    "portal-login",
    id_or_name=vault.id,
    type="credential",
    spec={
        "description": "Account Portal",
        "fields": {
            "username": {"type": "email", "sensitive": False, "required": True},
            "password": {"type": "password", "sensitive": True, "required": True},
        },
    },
)
```

</CodeGroup>

the fixed vault name is for a single-user demo. in a product, bind vault ownership to your authenticated user and isolate credentials across users and tasks.

## 2. Collect outside the agent

if the credential item has `action.name: "collect"`, show `action.url` only in your authenticated application. the end user opens it outside the agent-controlled browser and submits the form. don't print the item or link into an agent conversation. an existing ready item can be reused without another collection.

your backend can make up to ten long-poll requests, each waiting at most 30 seconds for readiness:

<CodeGroup>

```typescript TypeScript
let ready = false;
for (let attempt = 0; attempt < 10; attempt++) {
  const current = await kernel.vaults.items.retrieve(item.key, {
    id_or_name: vault.id,
    wait: 30,
  });
  if (current.type !== "credential" || current.id !== item.id) {
    throw new Error("credential item was replaced");
  }
  if (current.state.status === "ready") {
    ready = true;
    break;
  }
}
if (!ready) throw new Error("collection is still pending; resume from your application");
const browser = await kernel.browsers.create({ vaults: [{ id: vault.id }] });
```

```python Python
for attempt in range(10):
    current = kernel.vaults.items.retrieve(item.key, id_or_name=vault.id, wait=30)
    if current.type != "credential" or current.id != item.id:
        raise RuntimeError("credential item was replaced")
    if current.state.status == "ready":
        break
else:
    raise RuntimeError("collection is still pending; resume from your application")
browser = kernel.browsers.create(vaults=[{"id": vault.id}])
```

</CodeGroup>

stop on transport errors or conflicts rather than wrapping these calls in automatic retries. after a collection link expires, retrieve the item from your backend to get its current action.

## 3. Give the agent a scoped fill tool

let your existing agent navigate the attached browser to the configured login url and identify the form. for this controlled page, your tool can use fixed selectors. keep the vault, item key, browser id, url, and allowed fields bound by your backend, not selected from arbitrary model arguments.

<CodeGroup>

```typescript TypeScript
async function fillPortalLogin() {
  const current = await kernel.vaults.items.retrieve(item.key, { id_or_name: vault.id });
  if (current.id !== item.id || current.type !== "credential" ||
      !current.available_operations.some((operation) => operation.type === "fill")) {
    throw new Error("credential fill is unavailable");
  }
  const result = await kernel.vaults.items.performOperation(item.key, {
    id_or_name: vault.id,
    type: "fill",
    browser_id: browser.session_id,
    page_url: loginURL,
    fields: [
      { field: "username", selector: "#username" },
      { field: "password", selector: "#password" },
    ],
  });
  if (result.type !== "fill") throw new Error("unexpected operation result");
  return result;
}
```

```python Python
def fill_portal_login():
    current = kernel.vaults.items.retrieve(item.key, id_or_name=vault.id)
    if (current.id != item.id or current.type != "credential" or
            not any(operation.type == "fill" for operation in current.available_operations)):
        raise RuntimeError("credential fill is unavailable")
    result = kernel.vaults.items.perform_operation(
        item.key,
        id_or_name=vault.id,
        type="fill",
        browser_id=browser.session_id,
        page_url=login_url,
        fields=[
            {"field": "username", "selector": "#username"},
            {"field": "password", "selector": "#password"},
        ],
    )
    if result.type != "fill":
        raise RuntimeError("unexpected operation result")
    return result
```

</CodeGroup>

register this function with your agent framework as a tool with no caller-supplied parameters. authorize each invocation against the current user and task. don't let the agent change the backend's `LOGIN_URL`, and disable automatic tool retries as well as sdk retries.

`page_url` enforces an exact page match; it doesn't navigate there or create a credential destination allowlist. selectors also search descendant frames. for pages you don't control, validate the intended document/frame and destination in your controller before allowing disclosure. the item id check catches replacement before the call; it isn't an atomic precondition on fill. don't concurrently replace an item key used by an active task.

## 4. Handle filling and submission separately

give the agent instructions such as:

```text
navigate to the login page configured for this task and inspect the form without
reading populated credential values. invoke the portal-login fill tool once.
if its status is completed, submit the login form once and inspect the site's
response. completed means fields were filled, not that login succeeded.
if fill fails, returns unknown, or loses its response, stop and report the
existing attempt. don't retry, request the password, or use another fill path.
```

for `failed` or `unknown`, preserve the value-free result for reconciliation. don't dump the form's dom, filled values, or sensitive screenshots into logs. on successful fill, the agent still handles site-specific errors, navigation, and any additional authentication step.

when the task ends, delete the browser with `kernel.browsers.delete(browser.session_id)`. keep or delete the credential item according to your application's retention policy; deleting the browser doesn't delete the vault.

## Add totp when needed

add a sensitive `totp` field with a seed from trusted backend code. required totp fields must have a seed at creation; the hosted form can't collect one. on a later mfa page, invoke a separate fill for that field and its code input. KERNEL generates the code at write time. don't add the seed to the prompt, and don't retry an uncertain code fill automatically.

see [credential items](/vaults/credentials) for lifecycle and update rules, and [fill browser fields](/vaults/fill) for page matching, partial outcomes, and supported card fields.
