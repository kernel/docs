One entry per capability. Start here if you're evaluating Kernel or looking for the canonical page on something.

## Browsers

| Feature | What it's for |
| --- | --- |
| [Cloud browsers](/introduction/create) | Isolated Chromium in a [microVM](/info/unikernels), created in ~30ms. Headful by default, [headless](/browsers/headless) when you want a lighter, cheaper footprint. |
| [Browser pools](/browsers/pools) | A fleet of identically-configured browsers kept ready, so acquisition costs nothing. Idle browsers in a pool aren't billed. |
| [GPU browsers](/browsers/gpu-acceleration) | Hardware-accelerated rendering for WebGL, canvas-heavy pages, and video. |
| [Standby mode](/browsers/standby) | Suspends an idle browser and stops usage charges without losing session state. |
| [Termination and timeouts](/browsers/termination) | `timeout_seconds` as the safety net on every browser, up to 72 hours. |
| [Concurrency and limits](/browsers/concurrency-and-limits) | How many browsers you can run and create at once, and what happens at the limit. |

## Control

| Feature | What it's for |
| --- | --- |
| [How you drive the browser](/introduction/driving-the-browser) | The two decisions to make first: which control surface, and where your loop runs. |
| [Playwright execution](/browsers/playwright-execution) | Send Playwright code, run it inside the browser's VM, get the return value back. The recommended default. |
| [Computer controls](/browsers/computer-controls) | OS-level mouse, keyboard, and screen primitives — the surface computer-use models already speak. |
| [Playwright with computer-use fallback](/browsers/playwright-computer-use-fallback) | The recommended agent pattern: script what you can, fall back to pixels when the page fights you. |
| [Browser Loop](/browsers/browser-loop) | A framework-neutral browser tool catalog for your agent, with per-model compatibility handled. |
| [WebMCP](/browsers/webmcp) | Call the tools a site publishes to agents. On by default in every Kernel browser. |
| [File I/O](/browsers/file-io) | Uploads, downloads, and the session's filesystem. |
| [Shell access](/browsers/ssh) | SSH into the browser VM, run commands, forward ports. |
| [curl from the session](/browsers/curl) | Issue HTTP requests from inside the browser's network context. |

## Identity and auth

| Feature | What it's for |
| --- | --- |
| [Managed auth](/auth/overview) | Kernel performs the login — credentials, MFA, SSO — and keeps the session alive with background health checks and reauthentication. |
| [Profiles](/auth/profiles) | Persisted browser state (cookies, storage, logins, tabs) you attach to any browser. What managed auth writes into, and useful on its own. |
| [Credential storage](/auth/credentials) and [vaults](/vaults) | Where credentials live so they never enter your agent's context. |
| [1Password](/integrations/1password) | Use credentials from your own 1Password vaults for managed auth. |
| [Payments](/browsers/enable-payments-in-browser-agent) | Let an agent complete a checkout without handling card data. |
